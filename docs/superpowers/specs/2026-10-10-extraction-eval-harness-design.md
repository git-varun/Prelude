# Extraction accuracy eval harness — design

Date: 2026-10-10. Sub-project 1 of 4 in "optimize the Data Extraction flow" (accuracy).

## Goal

Make extraction accuracy measurable before changing it. Reported problems: missed facts, wrong values, marker mismatch, unreliable snippets/confidence. None are quantified today; only prompt-text and helper unit tests exist. The harness produces a repeatable baseline so later sub-projects (marker matching, recall/value accuracy, confidence/snippets) are judged by numbers, not impressions.

Out of scope: any change to extraction behavior, prompts, or matching.

## Decomposition (each gets its own spec → plan)

1. **Eval harness** (this spec)
2. Marker matching (`matchMarker` in `packages/shared/src/markers.ts`)
3. Recall and value accuracy (prompts/schema, optional verification pass)
4. Confidence calibration and snippet verification

## Inputs

Real patient reports in `docs/reports/` (6 PDFs: 3 large CBC/HbA1c panels, peripheral smear, APTT, chest X-ray; no prescription). They contain PHI and are gitignored (`docs/reports/` added to `.gitignore`). All have a text layer.

Assumptions: single patient's serial reports, small sample; text-layer PDFs bypass OCR, so OCR garbling (Textract/Azure/Google) is **not** measured. A scanned report is the follow-up for that.

## Components

- `apps/api/eval/fixtures/<name>.ocr.json` — `OcrResult` built per page with `pdftotext -layout` (`providerName: "pdftotext"`). Generated by `eval/buildFixtures.ts`; gitignored (derived from PHI).
- `apps/api/eval/fixtures/<name>.expected.json` — answer key: `documentType` plus expected facts `{ fieldType, markerLabel (as printed), canonicalMarker (expected `matchMarker` result or null), value, unit, referenceRange, asOfDate, sourcePage }`. Drafted by Claude from the PDFs, **reviewed and corrected by the user**; gitignored (contains PHI).
- `apps/api/eval/run.ts` — for each fixture, calls `AnthropicExtractionProvider.extractFacts(ocr, documentType)`, then scores. Run with `bun run eval` (requires `ANTHROPIC_API_KEY`; no DB, no server).
- `apps/api/eval/score.ts` — pure scoring functions, unit-tested with `bun test` on synthetic (non-PHI) inputs.
- `apps/api/eval/results/<timestamp>.json` — per-run output (gitignored) so runs can be diffed.

## Metrics

Facts are matched to expected by (normalized label, asOfDate), falling back to label only.

- **Recall** — expected facts found / expected facts, per fieldType and overall.
- **Precision** — extracted facts matching an expected fact / extracted facts (surfaces spurious facts).
- **Value / unit / range / date accuracy** — among matched facts, exact-match rate (value compared numerically when both parse).
- **Marker-match rate** — fraction where `matchMarker(extracted label)` equals expected `canonicalMarker`; unmatched labels listed.
- **Snippet verification rate** — fraction of candidates with non-null `sourceSnippet` after `verifiedSnippet`.
- **Confidence calibration** — mean confidence for correct vs incorrect facts, and a coarse reliability table (buckets 0–.5, .5–.8, .8–1).

Output: a console summary table plus the JSON file, including a per-fact miss/wrong list for debugging.

## Error handling

Provider failures (`failedFieldTypes`) are reported per fixture and excluded from precision but counted as misses for recall. Non-determinism: each run records model id and date; optional `--repeat N` averages runs.

## Testing

`score.ts` is unit-tested with synthetic data (matching, numeric compare, calibration buckets). `run.ts` is verified by running it against the real fixtures; its output is the baseline for sub-projects 2–4.
